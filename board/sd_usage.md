# SD 启动、I2C 采集与电池 SOH 推理

本文说明仓库当前上板文件、SD 卡准备、串口控制及屏幕输出。软件行为以 `src/ps/` 源码为准，硬件设计见 `src/hardware/`，HLS 最终版见 `src/hls/`。

## 上板文件

| 路径（相对仓库根目录） | 用途 |
| --- | --- |
| `board/fsbl.elf` | 第一阶段启动程序，初始化 PS |
| `board/system_wrapper.bit` | PL 硬件配置，包含推理加速器及相关接口 |
| `board/app_component.elf` | PS 应用，负责采集、SD 读写、DMA 与屏幕控制 |

| `board/flash/untitled.bif` | 原工程打包配置，顺序为 FSBL、bitstream、应用 ELF |

## SD 卡启动步骤

1. 准备板卡支持的 FAT32 SD 卡，将 `board/flash/boot.bin` 复制到卡根目录，并在卡上命名为 `BOOT.BIN`。
2. 将需要测试的 `data/NASA_SD/*.txt` 文件直接复制到卡根目录，例如 `1.txt`、`167.txt`。不要只复制外层目录：程序读取的是 `0:/1.txt`。不同数据目录可能有同名文件，复制前确认要使用哪一组。
3. 按板卡手册设置 SD 启动模式；断电后插卡并连接屏幕、传感器，再上电。具体拨码位置以所用板卡手册为准。
4. UART 设置为 115200、8N1。确认屏幕对象名称与下文一致；模型自检成功后显示 `idle`。
5. 发送 `FE 22 01 00 FD`，使用仓库 NASA 样本 `1.txt` 时，期望 `x1.val=9363`，显示 93.63%。此值是模型参考输出，不代表对实际电池精度的验证。
6. 测试采集时选择卡上尚不存在的编号，按下文发送 FE21；等待采集结束并显示 `done` 后，再用 FE22 对同编号文件推理。

SD 卡根目录示例：

```text
BOOT.BIN
1.txt
167.txt
```

## 重新打包启动镜像

已有 `untitled.bif` 使用原电脑的绝对路径，不能在其他机器上直接复用。需要重新打包时，在 `board/flash/` 下新建 `boot.bif`：

```text
the_ROM_image:
{
    [bootloader] ../fsbl.elf
    ../system_wrapper.bit
    ../app_component.elf
}
```

在已配置 AMD 工具环境的终端中，进入 `board/flash/` 后执行：

```powershell
bootgen -arch zynq -image boot.bif -o boot.bin -w on
```

该命令会覆盖当前目录的 `boot.bin`；如需保留已有镜像，先备份。使用同一最终硬件平台生成的 FSBL、bitstream 和应用 ELF，打包后仍需板上验证。仓库 `build/build.ps1` 当前只执行 HLS、综合和布局布线，不自动生成上述完整启动包。

## 串口命令

UART0，115200、8N1。发送二进制十六进制字节，不发送 ASCII 字符串，不需要回车。

| 帧 | 操作 |
| --- | --- |
| FE 21 01 00 FD | 等待电流 >1.6 A（拟合后） 后创建 1.txt 并记录；同名文件拒绝覆盖 |
| FE 22 01 00 FD | 读取 SD 根目录 1.txt 并推理 |
| FE 22 A7 00 FD | 读取 167.txt 并推理 |
| FE 21 E8 03 FD | 等待电流 >1.6 A（拟合后） 后创建 1000.txt 并记录 |
| FE 22 E8 03 FD | 读取 1000.txt 并推理 |

完整格式：FE 命令 编号低字节 编号高字节 FD。
编号与 i2c 工程相同，为无符号小端 16 位整数，范围 0～65535。
01 00 为 1；00 01 为 256；E8 03 为 1000。文件名不保留前导零。
帧内编号字节可以是 FE 或 FD。分段接收会等待完整帧，坏帧逐字节重同步。
接收使用中断和环形缓冲区，并在主循环轮询硬件FIFO兜底；两种读取互斥，避免重复读取或阻塞。
溢出时丢弃队列并提示重发。

### 屏幕状态

t0 仅显示运行状态，例如 result 1（文件编号不显示 .txt 后缀），不再追加 RX 字节计数和最近接收数据。
按钮事件代码是 printh FE 22 01 00 FD；采集按钮为 printh FE 21 01 00 FD。
SD err 8 表示采集文件已存在；Open 4 表示推理文件不存在。

## 采集及文件

FE 21 保留 INA226 实时测量和 SD 写入功能。
成功采样后等待约 1100 ms 再采下一点；校验失败不写入、不计数，下一轮主循环立即重试，不等待 1100 ms，也不执行主循环的 1 ms 延时。传感器转换和 I2C 通信本身仍需时间。收到 FE21 后进入等待状态；拟合电流严格大于 1.6 A 时创建文件并写入首点，记录中拟合电流连续 8 点 ≤−0.7 A 时关闭保存并重采样，完成后显示 done，确认停止的第 8 点不写入，前 7 点正常记录。判断使用有符号电流，非绝对值。结束后需重新发送 FE21 才会再次记录。
INA226 两字节接收使用应用层 20 ms 超时；无数据、数据不完整、NACK、硬件超时或未完成传输时返回失败，由 Sample 复位 IIC 后重试，避免进入 BSP 接收函数的无期限轮询。此行为以当前源码为准，上板时应使用与源码匹配的应用。持续硬件故障可能导致点数持续不增加；控制器复位不能保证释放被外部器件拉低的总线。
采集期间不调用 f_sync；满足连续 8 点停止条件时通过 f_close 刷新并关闭文件。f_write 仍可能触发实际 SD 写入，中途断电时尚未落盘的数据可能丢失。
记录取消 4000 点上限，可以少于或超过 4000 点；总时长由电流变化决定。
电流按 A 拟合：I_new = 1.23214862 × I_raw − 0.73766653。开始阈值为拟合电流 >1.6 A；停止阈值为连续 8 个有效采样点 ≤−0.7 A（约持续 7.7 秒），回升或采样异常重置计数。屏幕电流四舍五入为整数 mA，阈值比较不使用显示舍入值。
每行是电压 V#拟合电流 A（各六位小数），保留电流符号，例如：

    4.008750#1.726631

现有 NASA TXT 同样使用 4000 行 V#I，可直接使用。
采集结束显示 resample，电压与电流按相同位置 j×(N−1)/3999 均匀线性重采样为 4000 点，保留首尾点；单点记录重复为 4000 点。同编号 .raw 保留重采样前的拟合数据，.txt 保存 4000 点用于 FE22；已有 .raw 不覆盖并报错。处理失败不显示 done，保留原始数据；写入失败尝试恢复原 .txt，介质错误导致恢复失败时请检查 .raw。重采样占用固定约 64 KiB 输出缓冲，不随原始点数增加。
FE22 要求恰好 4000 行，读入时不重复做电流拟合。
等待阈值或记录期间，FE21/FE22 不启动新操作，不替换文件编号；等待时 t0 显示 wait 编号，记录时重复命令提示 recording。
推理不会修改文件。未找到文件、格式错误或 SD 失败时不发送新的 x1 结果。
读文件和推理期间暂停实时采样，完成后恢复；其间接收到的完整命令可排队处理。
同名文件存在时拒绝覆盖；采集错误停止记录，保留已写内容，t0 显示 SD 错误码。
记录使用的量纲与模型输入一致，但长度可变；实测曲线的采样时长和分布与训练数据是否一致，仍需另行验证预测精度。

## 屏幕输出

保留 i2c 工程已有对象：
- n0.val：电压 mV。
- n1.val：拟合电流 mA，有符号。
- n2.val：重采样前已写入的点数，可超过 4000。
- t0.txt：idle、wait 编号、rec 编号、resample、done、pred 编号、OK 编号或错误信息，最多 10 个字符，每秒刷新。

新增模型结果：
- x1.val = round(SOH百分数 × 100)，屏幕小数位设为 2。
不再计算或发送容量 x2。

代码通过 tjc_send_val("x1", "val", 整数) 发送。
val 参数是整数，不加字符串引号。每条命令以 FF FF FF 结束。
采用整数 Q12 运算，四舍五入；不依赖浮点 printf。

| 文件 | 模型 Q12 | x1.val | x1显示 SOH% |
| --- | --- | --- | --- |
| 1.txt | 3835 | 9363 | 93.63 |
| 167.txt | 3858 | 9419 | 94.19 |

1.txt 的实际发送内容为：

    x1.val=9363 + FF FF FF

串口不再输出普通 RESULT、自检日志或回车提示，避免污染屏幕命令。
错误详情通过 t0.txt 发送；失败时 x1 保留上一次结果，应以 t0 状态确认本次推理成功。
启动时执行两次模型自检。模型自检或 DMA 失败后禁用推理，采集仍可使用；复位并正确加载 PL 后重启应用。

## 硬件与上板

仓库硬件设计及约束中的接口配置：PS I2C0、UART0、SD0 均已启用。
- I2C0 使用 EMIO：SCL=Y7，SDA=U5。
- UART0 使用 EMIO：RX=Y6，TX=T5。
- SD0 使用 MIO40～45，卡检测 MIO10。
- LSTM AXI-Lite：0x43C00000；DMA：0x40400000。

使用当前包含 LSTM、I2C 和 UART 接口的硬件，下载新版 ELF。
仓库已包含启动文件；此次文档更新未连接板卡或验证这些二进制文件。

建议先发送 FE 22 01 00 FD，核对 x1=9363。
再选不存在的编号，例如 FE 21 E8 03 FD，等待电流触发停止并完成重采样，t0=done，
然后发送 FE 22 E8 03 FD，验证新采集文件的推理流程。


## 常见问题

| 现象或状态 | 检查项 |
| --- | --- |
| 无屏幕输出 | 供电、共地、TX/RX 交叉连接、115200 波特率及屏幕对象名称；确认 SD 启动模式和卡根目录的 BOOT.BIN |
| `IIC init` | I2C 初始化失败；检查平台配置与硬件版本 |
| 采集一直 `wait` | 拟合后的有符号电流尚未严格大于 1.6 A；检查传感器及电流方向 |
| 点数不增加 | 检查 INA226 接线、地址及通信；失败采样不会计数 |
| `Mount ...` | 检查 SD 插卡、FAT 文件系统及 SD 硬件配置 |
| `Open 4` | 编号对应 TXT 不在卡根目录，或文件名不符 |
| `SD err 8` | 文件已存在；换用未使用的编号，并检查同编号 `.raw` |
| `Need 4000` | 推理输入必须恰好 4000 行 |
| `TXT format` / `TXT IO err` | 检查 V#I 文本格式或 SD 读取情况 |
| `DMA init` / `Test fail` | 检查 PL 是否加载、硬件地址配置、应用和 bitstream 是否匹配 |
| 推理失败但 x1 仍有数值 | x1 保留上一次结果；结合 t0 判断本次操作是否成功 |
